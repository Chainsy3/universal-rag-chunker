01 / INPUT FORMATS

不同格式，共用一条处理路径。

解析器理解文件格式。
切块策略专注内容边界。

文件格式提取能力来源定位
TTXT / MarkdownUTF-8 原文、标题、段落与围栏代码原文字符偏移
PPDF按页提取已有文本层页码
WWord · DOCX正文、标题、表格及嵌套表格文字正文元素索引 / 表格行
XExcel · XLSX全部工作表、单元格与公式原文工作表 / 行列 / 单元格坐标

扫描 PDF 的 OCR、旧版 .doc / .xls、复杂 PDF 表格恢复暂未支持。Excel 公式以文本保留，不执行计算。查看完整范围 ↗

02 / MODULAR BY DESIGN

通用核心，明确的扩展边界。

不把行业词表写进默认行为。
需要领域规则时，显式启用插件。

03Strategy确定切块边界

A

策略可替换

fixed 提供字符窗口基线；recursive 优先利用结构、换行与句界，再按字符兜底。

B

校验贯穿流程

检查长度、顺序、引用范围与内容重建。相同输入和组件配置生成相同文档与切块 ID。

C

导出保持独立

Python API 返回结果后再决定是否写盘。输出 JSON / JSONL，不绑定向量数据库。

03 / TRACEABLE OUTPUT

切块之外，
还有上下文与出处。

每个 Chunk 通过 source_spans 关联 IR 文本。
页码、正文位置或工作表位置也可直接随块查看。

04 / GET STARTED

把第一份文档，
交给 Chunker。

克隆仓库，安装需要的格式依赖，
使用同一个命令处理五种格式。

阅读完整安装指南 ↗
Python 3.11+ · 建议使用虚拟环境
git clone https://github.com/Chainsy3/universal-rag-chunker.git
cd universal-rag-chunker
python -m pip install ".[all]"
urc chunk examples/guide.md --output out
urc validate out/document.ir.json --chunks out/chunks.jsonl

也支持分别安装 .[pdf]、.[word]、.[excel]
